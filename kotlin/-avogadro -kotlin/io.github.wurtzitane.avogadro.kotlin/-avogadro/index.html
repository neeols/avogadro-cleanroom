Avogadro

object Avogadro

Kotlin functions for creating molecule definitions, editing copies, and registering your mod's molecules.

Import io.github.wurtzitane.avogadro.kotlin.*. All receiver blocks expose the builder methods for atoms, bonds, item/fluid matches, atom details and polymers. A builder collects those choices before creating a definition. Nothing is registered until register or replace. No client classes are referenced here; these functions are safe in common mod code. The host must supply a compatible Kotlin standard library (for example Forgelin).

Builds an assembly recipe, without expanding adjustable parameters. configure exposes named parts, groups, repeats, transforms and explicit links. Call the result's build() for a finite recipe or pass it to a network definition.

fun edit(source: StructureFragment, configure: StructureEditor.() -> Unit): StructureEditResult

Edits a copy of source and returns both geometry and original-to-final indices. Each operation addresses current indices; bulk deletion resolves its whole selection first. Removed atoms map to -1. Element changes clear old atom-specific configurations. Materialize a unit cell or template preview before editing topology.

fun fragment(configure: StructureBuilder.() -> Unit): StructureFragment

Authors a reusable finite fragment. Coordinates are explicit; no chemistry is inferred. Use addAtom when you need a returned index, then attachment to name it. The returned fragment owns immutable copies of the builder's data.

molecule

fun molecule(id: String, configure: MoleculeBuilder.() -> Unit): MoleculeSpec

Builds a definition whose values cannot be changed afterward. It is not registered until you submit it. id is a stable namespaced ID, such as mymod:water; configure runs once. Validation and SMILES geometry use the Java builder's rules and exceptions. For expensive geometry, use the builder's buildAsync() directly.

fun register(owner: String, vararg definitions: MoleculeSpec): CompletableFuture<MoleculeView>

Registers definitions under owner, preserving that owner's other entries. The future completes after validation and publication; failures retain the previous view. Do not block a game thread with join(); attach thenAccept/whenComplete instead. Registration scopes belong to your mod ID, not to an individual screen.

fun replace(owner: String, configure: MoleculeBatch.() -> Unit): CompletableFuture<MoleculeView>

Replaces one owner's entire layer, including tags, with a fresh configure batch. Omitted entries are removed only after the whole replacement validates successfully. Build definitions before this call; the block is a commit callback, not a UI callback. Use the Java batch's register, itemTag and fluidTag methods directly.
